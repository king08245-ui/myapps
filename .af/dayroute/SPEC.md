# 하루동선 (폰 앱판)

**한 줄 목적**: 하고 싶은 일을 문장으로 적으면(예: "광화문 교보문고 2시간, 근처 국밥집 점심, 정독도서관, 이태원 복귀"), 실제 장소(카카오)와 실제 이동 시간(자가용·대중교통)으로 하루 시간표와 경로를 짜 준다. PC를 켜 두지 않아도 **폰에서 바로**.

**누가 언제**: LEE가 밖에서 폰으로 그날 동선을 짤 때, 집에서 주말 일정을 미리 짤 때. 나중에 king_bot도 같은 서버 주소로 부를 수 있다.

## 원본(PC판 dayroute-app, 2026-10-08판)에서 이어받는 기능 — 완료 조건
| 기능 | 완료 조건 |
|---|---|
| 문장 해석 | 키워드 해석(AI 키가 있으면 AI). 적은 이름은 그 이름으로, "A 근처 B"는 A 가까이, "근처 국밥집"은 앞 장소 가까이, "복귀/귀가"는 도착지 |
| 식사 가격대 | 가성비/보통/상관없음 — 카카오 음식 분류로 추정 |
| 실제 이동 | 자가용(카카오모빌리티), 대중교통(ODsay), 500m 안 도보. 구간마다 이동수단 바꾸기, 대중교통 다른 경로(지도 회색 선) 고르기 |
| 코스 고치기 | 장소 바꾸기(경로 근처·지도 누른 곳 근처), 여기에 추가, 머무는 시간 ±30분, 순서 바꾸기, 빼기, 못 찾은 곳 바꾸기, 자동 추천으로 되돌리기 |
| 즐겨찾기 경로 | 저장·불러오기·삭제(두 번 눌러 확인) — 10/17부터 화면 이름 '즐겨찾기 경로'(장소와 구분) |
| 이미지로 저장 | 시간표+약도 PNG (폰은 공유 시트) |

## 폰 앱판에서 바뀌는 것
| 부분 | 어디에 | 이유 |
|---|---|---|
| 화면(설치형 앱) | GitHub Pages `king08245-ui.github.io/myapps/dayroute/` | 홈 화면 설치·오프라인 화면, 다른 앱과 같은 주소 |
| 일정 계산 서버 | Cloudflare Worker (`worker.js` 한 파일을 대시보드에 붙여넣기) | 키를 폰에 두지 않음, 잠들지 않음, 무료 |
| 즐겨찾기 | 폰 저장(localStorage `dayroute:v1`) + 백업 내보내기/가져오기 | PC판 favorites.json도 그대로 가져오기 |
| 남이 키 사용량을 못 쓰게 | 접속 코드(ACCESS_CODE, 한글 가능) | 앱 설정에 한 번 넣으면 폰이 기억 |

- 새로 더한 것: 📍 현재 위치에서 출발, 지난번 일정 자동으로 다시 보여 주기, 예시 일정 보기(서버 없이 화면 둘러보기), 설정 링크(`#server=…&code=…`)
- 무료 Worker 한도(요청 한 번에 바깥 API 50번)에 맞춰 호출 수를 세고, 넘으면 남은 이동 계산 몫을 지키며 검색을 줄인다(`short` 표시 → "다른 곳으로 바꾸기"로 고르기).
- ODsay 웹 키는 PC판에서 등록한 `http://localhost:3000`을 Referer로 보낸다(ODSAY_REFERER로 바꿀 수 있음).

## 독립 검수·실제 키 시험 뒤 바뀐 것 (10/11)
- **즐겨찾기·지난 일정은 복사본**: 저장한 뒤 화면에서 고쳐도, 불러와서 고쳐도 저장본은 그대로.
- **고치기는 성공했을 때만 반영**: 신호가 끊기거나 서버가 거절하면(12곳 넘음 등) 일정·상태가 그대로라, 다시 눌러도 한 번만 반영. 12곳 일정에서 '여기에 추가'는 바로 안내.
- **계산 중 잠금**: 응답을 기다리는 동안 고치기·즐겨찾기 버튼을 잠가 두 번 눌러도 한 번만. ★저장 두 번은 하나만, 즐겨찾기 삭제는 '한 번 더'를 보고 다시 눌러야 지움(연달아 두 번은 무시).
- **종류만 적은 말**: '필라테스·브런치·기념관'은 적은 말 그대로 근처에서 찾음(헬스장·백반집·미술관으로 바꾸지 않음). '1시간 30분'은 90분(PC판은 60분으로 읽던 문제).
- **'서점' 같은 종류 검색**: 카카오가 그 종류로 분류한 곳을 먼저(교보문고 안 안경점·물류센터가 위로 오지 않게), 장소 추가 검색에서 주차장 제외.
- **다시 연결**: 열 때 신호가 없었어도 신호가 돌아오면 저절로, 또는 '일정 짜기'를 누를 때 다시 붙음. 신호가 없을 뿐이면 설정 칸을 열지 않음.
- **같은 주소의 다른 앱 저장본 보호**: 서비스워커가 자기 옛 저장본(`dayroute-`)만 지움(채널 맛집수첩과 서로 지우던 문제). 서비스워커 v2.
- **새로 적던 입력 유지**: 지난 일정이 있어도 그 뒤 적던 요청·출발지·시각·이동수단은 다시 열었을 때 그대로.
- **예시 일정**: 서버가 연결돼 있으면 예시를 본 뒤에도 일정 짜기·고치기가 됨. 예시는 실제 키로 짠 공덕역 대중교통 일정.
- **접속 코드**: 틀린 코드에는 1초 늦게 답함(마구 맞혀 보기 방지), 코드가 6자 미만이면 연결할 때 더 길게 바꾸라고 안내.
- **구간 다시 쓰기**: 고칠 때는 앞서 계산한 구간·출발지를 같이 보내 바뀐 곳 앞뒤만 새로 계산(머무는 시간만 바꾸면 바깥 호출 0번) — 무료 Worker 한도(요청당 50번·CPU 10ms)와 ODsay 하루 횟수를 아낌. 계산이 한도로 끊기면 '서버 주소 확인'이 아니라 '한 번 더 눌러 주세요'.
- 한 곳짜리 일정에서 빼기는 안내만(요청 문장으로 다시 짜지 않음), 폰이 보낸 활동 목록은 서버가 모양을 다시 맞춤.

## 운영 — 서버 켬 (10/11)
- 서버: `https://dayroute.king08245.workers.dev` — LEE의 Cloudflare 계정 Worker `dayroute`(workers.dev 하위 도메인 king08245). worker/worker.js(VERSION 2026-10-11b)를 대시보드 편집기에 붙여넣어 배포. Cloudflare Access 보호는 끔(폰 앱이 불러야 해서)
- 비밀 4개(KAKAO_REST_KEY·ODSAY_API_KEY·KAKAO_JS_KEY·ACCESS_CODE)는 LEE가 직접 입력 — 값은 어디에도 적지 않음
- 카카오 developers 앱 '용산지도' → 앱 → 플랫폼 키 → JavaScript 키 → JS SDK 도메인에 `https://king08245-ui.github.io` 추가(기존 `http://localhost:3000` 유지). REST 키는 호출 허용 IP 제한 없음
- 확인한 것: github.io에서 /api/status CORS 200·키 3개 읽힘·접속 코드 켜짐, 지도 SDK 로드·지도 만들기 OK, 설정 링크(`#server=`)로 열면 서버 칸이 채워지고 코드만 물음. 실제 일정 짜기(접속 코드 필요)는 LEE가 폰에서 처음 써 볼 때 확인
- 폰 연결 QR: `…/dayroute/#server=https%3A%2F%2Fdayroute.king08245.workers.dev` (코드는 넣지 않음 — 코드는 폰에서 직접 입력)
- 코드만 바꿀 때: Workers 및 Pages → dayroute → Edit code → 전체 바꾸기 → Deploy(비밀은 그대로 남음)

## 즐겨찾기 장소 (10/17) — "집, 도서관, 내가 가는 카페"
LEE 요청: 하루동선에 즐겨찾기 장소. 서버(Worker)는 고치지 않음 — 폰 화면만 바꿔 바로 쓰게(대시보드에 다시 붙여넣을 필요 없음).

| 기능 | 완료 조건 |
|---|---|
| 저장 | 패널 '＋ 장소 추가' → 부를 이름(예: 집) + 이름·주소로 찾기(카카오 지도 SDK services: 키워드 20km 안 정확도순 → 없으면 전국, 숫자가 있으면 주소 검색도) → 저장. '📍 지금 있는 곳으로 저장'(이름 먼저, 주소는 카카오 coord2Address). 시간표 카드 '⋯ → ☆ 장소 저장'(기본 이름 = 장소 이름). 30곳까지, 같은 이름은 새 위치로 바꿈 |
| 출발지 | 출발지 칸 아래 칩(누르면 출발지, 고른 칩 진하게) · 출발지 칸에 이름만 적어도 됨(자동완성 datalist). 보낼 때 저장한 좌표(originLL)로 — 서버가 '집'을 이름으로 찾지 않음 |
| 요청 문장 | '도서관 2시간, 점심, 단골카페 1시간, 집' → 저장한 곳 그대로. 맨 끝에 시간 없는 '집'·'귀가'·'집으로 복귀'·'집에 가기' → 집으로 돌아오기(도착). '집에서 출발'·맨 앞 시간 없는 '집' → 출발지를 집으로(출발지 칸도 바꿈). '집 근처 카페' → 저장한 집 1.2km 안에서 먼저 고름(/api/nearby) |
| 표시 | 시간표 카드에 ★ 이름(활동 이름이 그 이름으로 시작하면 한 칸: ★ 도서관, ★ 집 복귀). 늘 가는 곳엔 '주차 확인'을 붙이지 않음 |
| 고치기 | 바꾸기·여기에 추가 검색 칸 위 즐겨찾기 장소 칩 → 그곳으로 바꾸거나 더함 |
| 관리 | 이름 바꾸기(겹치면 안내, 출발지 칸의 옛 이름도 바꿈) · 삭제(두 번) · 백업 내보내기/가져오기에 포함 |
| '귀가'를 못 찾음 | 집을 저장하지 않았으면 '찾지 못함' 카드에 '＋ 집 저장' 버튼 |

### 어떻게 (정한 것)
- 활동 번호를 알아야 그 자리에 저장한 곳(picks)을 넣을 수 있어, **요청에 저장한 이름이 나올 때만** 폰에서 먼저 해석해 `acts`+`picks`를 함께 보낸다. 해석기는 서버 ruleParse를 그대로 옮김(옛 사파리용으로 lookbehind 정규식 하나만 같은 뜻으로 바꿈). 서버 것을 고치면 폰 것도 같이 — 검수 흐름 `client_parser_matches_server`가 23개 문장으로 둘을 비교한다. 이름이 안 나오면 예전처럼 문장만 보냄(서버가 해석, AI 키가 생기면 AI).
- 같은 이름으로 볼지: 띄어쓰기·대소문자·끝 조사(으로·에서·에게·까지·부터·로·에·을·를)를 빼고 **똑같을 때만**('정독도서관'은 '도서관'이 아님). '우리집'·'내집' = '집'. 부를 이름이 아니어도 저장한 곳의 실제 이름과 같으면 그곳.
- 토막 나누기는 서버와 같고(쉼표·그리고·→·'먹고/보고/가고/하고' 뒤), 즐겨찾기 쪽에서만 '출발해서/출발한 뒤/출발 후' 뒤도 나눔.
- 집으로 보는 이름: 집·우리집·내집·자택·본가·숙소(아이콘 🏠). 나머지 아이콘은 이름·분류로(📚☕💪🏢🏫🌳🍚, 없으면 ⭐).
- 좌표로 출발한 일정을 고칠 때(지운 즐겨찾기 등)는 그 일정의 출발점 좌표를 다시 씀 — 이름으로 다시 찾아 출발점이 바뀌지 않게.
- 카카오 SDK를 `libraries=services`로 부름(같은 JS 키). 키가 없거나 SDK가 안 뜨면 이름 찾기 대신 '지금 있는 곳으로 저장'을 안내.
- 검수: 카카오 SDK 흉내 `test/kakao_stub.js`(flows가 /api/status의 jsKey를 'test'로 바꿔 부르게 함), PC판 즐겨찾기 파일이 없으면 같은 모양의 `test/pc_favorites_sample.json`.
